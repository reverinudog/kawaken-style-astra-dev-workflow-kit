# HTML説明と回答の使い勝手を持ち運べる形にする

## 目的と範囲

説明・提案・相談をHTMLで表示し、回答の保存と通知によって同じCodexタスクを再開する機能を汎用版へ収録する。
説明資料、比較回答、下書き、一覧、一括提出、受付、通知待ち、受領、タスク選択、タブ整理、接続復旧を対象にする。
既存の共通HTML受付の保存・通知分離を基に、個人用パス・作品情報を含めず配布する。

## 維持条件

- 元の製品・個人共通skillを変更しない。共有するのは汎用コード・手順・ひな型だけ。
- 説明と相談はHTMLを既定にし、短い進捗・単純報告はチャットでよい。
- 左右の比較範囲を揃える。回答は未選択を既定とし、保留と未回答を分ける。
- 既存URLと保存キーを維持。未提出の入力・古い版の入力を保持し、自動提出しない。
- 保存・通知受付・モデル受領を区別する。提出がない時はAIも通知処理も動かさない。
- ブラウザから再開先・保存先を変更させず、旧回答を別タスクへ再通知しない。
- 通知の成否不明は自動再送しない。実接続未確認を成功と報告しない。
- privateを維持。一般公開・新しい有料サービス・他タスク生成へ拡張しない。

## 設計

Python標準ライブラリでHTTP受付・原子的保存・SQLite通知待ちを扱い、
Node.jsの小さなアダプターで現在のCodexデスクトップへ接続する。
ホスト固有の接続は起動環境から受け取り、ファイルに秘密値を埋め込まない。
回答資料と実データは.local/以下へ保存する。

- [x] 説明だけ／比較回答／タスク選択の入口が資料とskillから使える。

- [x] HTTP保存、二重提出、版不一致、不正送信、非公開ファイルの非配信を確認。
- [x] 通知待ち、実行中待機、成否不明、再起動、別タスクへの誤配信防止を対象テストで確認。
- [x] 現在のアプリへの接続と、テスト提出後の同一タスク再開・受領を確認。
- [x] 親レビュー、独立読み取り専用レビュー、必要な修正・再検証を完了。
- [x] 文書チェックと固有内容・秘密の配布前チェックを完了。

## 結果

実装済み。Windows、Node.js 24、Python 3.10、Codex内蔵ブラウザで確認。
文書チェック49ファイル・13skill、既存Node6テスト、HTML受付Node4/Python14テスト成功。
新skillの書式validator、配布内容scanと外部denylistの確認は成功。
比較画面は1920×1080でも確認。説明専用と一覧からのタスク選択も描画確認した。

親の確認で、再起動時の宛先固定、送信中終了の成否不明化、受領直後に遅れて返る通知結果、
提出後の編集表示、保存記録破損時のURL維持を修正・確認した。
独立レビューの2件は、版別の下書き保存と、通知拒否が確定した場合だけの明示再試行で対応し、対象テストは成功。
読み取り専用フォローアップで前記2件の解消を確認。
追加指摘の空・欠損した起動記録は、必須フィールドと型の検証で新規扱いにしないよう修正し、回帰確認した。

実接続statusは現在タスクと一致。テスト提出のHTTP保存と通知待ち登録、同じURLでの受付再起動を確認済み。
親の処理終了後、提出イベントで同じタスクが自動再開した。保存JSONを読み、受領コマンドでreceivedへの遷移を確認した。
実回答へ流用せず、接続検証として完了。検証記録を更新し、元の依頼どおりprivateリポジトリへ収録する。
