# 切り出し方針

実運用の文書構成と開発判断を抽出し、独立した汎用版として再記述した。
原文フォルダやGit履歴の一括複製は行わない。

| 分類 | この版での扱い |
| --- | --- |
| 共通入口・文書の責任分離 | 採用 |
| 計画、実装、レビュー、検証、引き継ぎ | 汎用化して採用 |
| Astra親と必要時の独立レビュー | 採用 |
| 画面、保存、AI、制作、配布の品質確認 | 特定製品の値・名称・コードを外して採用 |
| スキルのルーティング | astra-*として新規作成。手順本文は一箇所で管理 |
| 文書参照・タスク登録チェック | 製品への依存がない小さな検査ツールとして新規実装 |
| 言語、画面サイズ、Git方針、実行コマンド | PROJECT.mdで導入先が選択 |
| 製品コード、設定、名称、シナリオ、素材、セーブ | 含めない |
| 過去のタスク、教訓原文、スクリーンショット、会話 | 含めない |
| 個人用hook、絶対パス、外部アカウント、認証 | 含めない |
| 外部配布されたskillやプラグインの本文 | 同梱しない |
| 説明HTML・比較回答・途中保存・一覧・提出 | 表示・受付・復旧・タブ運用まで汎用化して同梱 |
| 同じタスクの再開 | 保存・通知待ちを同梱。アプリ接続部分は小さなアダプターに分離し、導入先で実接続確認 |
| 制作CLI、モデル別外部実装者 | 元環境依存の実装は同梱しない。必要なら導入先で別途接続する |

原環境への逆同期はしない。汎用化は動作の同等保証や、全分野での実績を意味しない。
この版の確認は[検証記録](validation.md)へ記載する。
