# リリースと配布

対象channel、version、成果物、公開先、利用者、停止点を今回の依頼とPROJECT.mdで確認する。
ゲーム、デスクトップアプリ、Webサービスで配布方式を固定しない。

## 準備と検証

主要経路の選択は[リリースQA](release-qa.md)、利用者向け文案は[更新情報](release-notes.md)を使う。

- 同じコードで有効な既存検証を再利用し、配布境界の不足だけ補う。
- packageやbuildに秘密、debug用設定、実データ、作業資料が入らないか確認する。
- 成果物から隔離環境へ導入し、起動、主要操作、保存・再開、更新を影響に応じて確認する。
- Webでは設定、権限、DB migration、復旧、health確認を対象環境で確かめる。
- 生成物のversion、hash、設定と試験対象を対応付ける。未試験のbuildへ結果を流用しない。

公開前に具体的な成果物と設定を確定する。一般公開、費用、法的同意、本番データの更新は承認範囲を守る。
privateへの保存をpublic化の許可とみなさない。公開設定は実行後に再取得して確認する。
公開済みと報告する前に、対象version、配布状態、導入・閲覧経路を確認する。

更新情報は利用者に何が変わるかを書き、内部実装や未確認の効能を並べない。
承認済み文章の意味を保つ短縮は通常の編集として行い、新しい主張は確認する。
