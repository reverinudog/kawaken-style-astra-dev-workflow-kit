# レビュー

読み取り専用レビューでは、ファイルとGit状態を保持して指摘を返す。
実装担当の親は最終差分を意識して見直し、今回の範囲にある実際の問題を自分で直す。

確認の優先順は、要件違反・挙動回帰、利用者の不具合、契約の検証不足、重複した責任、
原因を残す例外処理、範囲外変更。差分の小ささだけで良し悪しを判断しない。
構造変更では編集していない呼び出し元や保存・中断時の契約も確認する。

指摘は影響、再現条件または追跡根拠、file/line、修正条件を示す。
仮説、任意の好み、確認できた欠陥を区別する。指摘数を埋めるための改善案を作らない。
UIは[全画面の確認](ui.md)、製品AIは修正後に[入出力確認](ai-contract.md)も行う。

親の修正後は[影響した検証](verification.md)だけを再実行し、未変更の成功結果を保持する。
[担当の条件](ownership.md)に該当すれば一人の独立レビューを行う。
必要な仕様判断が生じた時だけ具体的な選択肢を提示する。

完了時は指摘と修正、確認結果、未確認の点を伝える。
実装の完了だけを理由にcommit・merge・公開へ進まない。既に承認された工程は再確認せず進める。
