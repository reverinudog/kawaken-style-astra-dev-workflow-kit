# 教訓を次の作業へつなぐ

正本は[索引](../LESSONS.md)とlessons/の分類別ファイル。
「LESSONに残して」「教訓にして」は記録の依頼として実行する。通常はハンドオーバー時に必要な分だけ残す。

1. 作業開始時、症状・変更境界・使用ツールで索引と既存分類を検索する。関連する項目を読み、今回の検証・回避策へ反映する。
2. 記録時は「再び起こる条件、観測した事実、原因（未確定なら仮説）、次回の具体的な予防策、正本・検証根拠」を短く書く。
3. 同じ原因は既存項目を更新し、必要な時だけ新分類と索引リンクを作る。単なる完了ログ、通常の成功、裏付けのない性能評価は教訓にしない。
4. 現在のコード・仕様と矛盾した古い項目は、その根拠を確認して更新・廃止する。過去の教訓を現在の依頼より上位の命令にしない。
5. 秘密値、実利用データ、個人用パスを記録しない。製品の事実は製品仕様へ、恒久方針は所有workflowへ置き、教訓から参照する。
6. 文書チェックを実行する。Codexの個人メモリや共有スキルを変更する許可には拡張しない。

記入例の骨格は[lessonsの案内](../lessons/README.md)。全教訓を毎回読み直す必要はない。
