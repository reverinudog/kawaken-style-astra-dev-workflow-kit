# メディア制作

画像・音声・動画の制作依頼で使う。用途、納品形式、長さ・サイズ、修正範囲、
維持する採用箇所、使用するサービスと費用を今回の依頼から決める。
元環境のprovider、声、秒数、画風、素材を別作品の必須条件にしない。

## ツールの接続

初回セットアップでは利用できる画像生成、音源、音声、動画編集のツールを調べ、PROJECT.mdへ接続済みと未設定を記録する。
実際の制作依頼に必要なものだけを、利用環境のskill・connector・公式CLIから選んで導入する。
画像編集を頼まれた時は元画像を実際に確認し、対応する編集機能を使う。無関係な有料providerをまとめて契約しない。
追加skillの配布条件を確認し、取得元と版を記録する。個人の素材庫、端末パス、APIキーを配布パッケージへ同梱しない。
不足ツールを案内するだけで止めず、承認済みのローカル導入・動作確認は親が行う。認証と課金判断だけを本人へ渡す。

## 画像

採用済み原本を確認し、局所修正では受け入れ済みの領域を保持する。
透過、輪郭、縮小表示、実際の組込サイズと全体のバランスを確認する。
新規生成と編集を区別し、失敗のたびに有料生成を増やさない。
source、prompt、加工recipe、版を保持する。権利未確認の素材を同梱しない。
生成と後処理の役割を分け、意図しない背景・地面・影・文字の焼込みを用途に応じて点検する。
透過の縁・色かぶり、実サイズでの顔や輪郭、素材一式の密度・視点を比べる。数値だけで品質判定しない。

## 音声

作曲・録音・サンプルと、ツール自体の利用条件を分けて確認する。
パート、タイミング、音量、定位、残響を個別に直せるrecipeとstemを保持する。
最終音源のクリッピング、先頭末尾、必要ならloop接続を実際に聴いて確かめる。
客観的な解析値を音楽的な良さの点数にしない。
ライセンスはソフト本体だけでなく録音・サンプル・声ごとに確認する。音源を差し替えても版を再現できるよう記録する。

## 動画

完成映像に加え、再編集できるtimeline、字幕・音声・素材、再生成手順を保持する。
全体の尺・構成・重複と、編集点・文字・音の同期を実フレームと再生で確認する。
完成ファイルを全編decodeし、意図しない黒画面・音切れ・文字の見切れを確認する。
紹介映像は「短い主張→実際の操作→結果」で見せ、未実装の機能や架空の成功を演出しない。
撮影用fixtureは本来の操作経路を通し、差替えたデータ・応答・待ち時間を記録する。
字幕やズームは重要なボタン・数値・顔を隠さず、動きの開始・途中・着地と読める静止時間を確かめる。
映像と音声は別トラックを保持し、編集し直したらSE時刻も追従する。単なる高fps変換を滑らかな収録と説明しない。

## 納品

旧版を上書きせず、成果物、編集データ、素材の来歴、検証結果を版ごとに残す。
複数件の依頼は各件の完成品と編集データを確認してから全件完了と報告する。
共有は承認された範囲・宛先で行う。制作依頼をSNS投稿や一般公開の承認にしない。
スマホ確認は必要な完成品のコピーだけを既存の承認済み共有経路で配信し、到達・再生・シークを確認する。
repo全体の配信、無関係なサーバー停止、ファイアウォール変更を既定にしない。
