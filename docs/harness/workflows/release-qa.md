# 配布前の主要経路を確認する

配布直前や広い品質確認で使う。PROJECT.mdと製品の重要な経路から、影響と未確認箇所を選ぶ。

| 境界 | 代表的な確認 |
| --- | --- |
| 新規導入 | 起動、初期設定、キーなし・権限なし、最初の主要操作 |
| 継続利用 | 既存データの読込、更新、保存・再開、長時間利用 |
| 通信・AI | 遅延、失敗、不正応答、中断、再試行、費用の重複 |
| 画面 | 通常・空・長文・最大件数、遷移、戻る、入力・focus |
| 配布 | 実成果物、設定、秘密混入、更新経路、公開範囲、復旧 |

全機能の組合せ網羅ではなく、変更した境界と影響の大きい主要経路を確認する。
既存の成功を再利用し、対象のcase/fileと成果物のhash・versionを記録する。
実buildの起動、console error、欠損asset、必要ならメモリ・応答の劣化を実物で確かめる。
関係のない全suiteやE2E全体を自動実行しない。選び方は[検証](verification.md)。
発見した無関係の改善は別タスクへ記録し、配布作業を無断で拡大しない。
