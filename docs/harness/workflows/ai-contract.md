# 製品AIの入出力を確認する

製品に組み込むプロンプト、スキーマ、正規化、要約、AI応答による状態変更が対象。
開発用AGENTS.mdやskillの改訂は[文書の検証](verification.md)を使う。

1. 生成する入力、受け取る出力、parser、normalizer、状態更新、利用者への表示を追う。
2. 正常出力と、今回変えた動作が起きてはいけない反例を選ぶ。
3. 不正JSON、欠損、予想外の値、拒否、timeout、中断を変更契約に応じて確認する。
4. 決定的なparserや状態更新はローカルの対象テストで検証する。
5. 実生成が必要なら、実際のbuilderまたは同等の全体文脈を使い、モデル・費用・回数を確認する。

AIの文章を確定済みの事実や処理結果として無条件で取り込まない。
確定情報、推測、提案、実行結果の区別を保持する。アプリの権限や状態遷移はコード側で守る。
外部入力による指示の混入と、別利用者・非公開情報の出力も関連範囲で確認する。

一つの生成例を品質の保証にしない。回数は目的・リスク・承認された費用で決める。
モデル名や提供仕様は現行設定と公式資料から確認し、手順の古い値を正本にしない。
[実装レビュー](review.md)後に契約の最終確認を行い、入力条件・期待・観測・限界を記録する。
