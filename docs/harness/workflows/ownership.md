# 担当と独立レビュー

既定では親Astraが調査、証拠収集、設計、実装、自己レビュー、修正、最終検証を担当する。
新規画面も同じ。調査や実装を「レビュー」と呼び替えて分担しない。別モデルや外部エージェントへ自動移譲しない。

次の場合、一つの範囲に一人の独立した読み取り専用レビュアーを使う。

- 自己レビューの修正で実装を大きく書き換えた。
- 保存互換、課金、認証・権限、プライバシー、製品AIの入出力など高リスク契約を変えた。
- 担当・承認・完了条件に関わる運用指示やskillをまとまって改訂した。
- ユーザーが独立レビューを明示した。

差分、要件、維持する契約、検証済みの証拠を渡す。答えや疑うべき不具合を誘導しない。
レビュアーは編集、Git変更、外部送信、広範囲テストを行わない。
具体的疑義の確認以外で成功済みテストやブラウザ確認を重複させない。
モデルと推論設定は親を継承し、明示指定がある場合だけ変更する。

親は待機中に独立した残作業を進め、完了通知を待つ。同じレビューのやり直しや短い間隔のpollは行わない。
指摘は親が確認・修正し、影響する検証だけを再実行する。
追加修正が小さく高リスク契約へ触れないなら、再レビューを連鎖させない。

機能が利用できない場合は親レビューを完了し、独立レビューが未実施であることを明記する。
未実施レビューを済んだものとして扱わず、導入先に必須ゲートがあればその工程で停止する。
