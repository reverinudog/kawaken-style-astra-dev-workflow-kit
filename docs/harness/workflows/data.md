# データと互換性

対象データの正本、所有者、読取・書込経路、初期化・終了・再開を追う。
保存形式を変える時は既存版の読込、移行の再実行、欠損・破損、中断後の復旧を必要な範囲で確認する。

実利用データをfixtureにコピーせず、契約を再現する合成データを使う。
書込検証は隔離領域で行い、環境の切替が実際に効いたことを確かめる。
読み込み失敗を空データの成功として上書きしない。失敗時に既存データを保護する。

DBやクラウド同期では、権限、競合、リトライによる重複、トランザクション境界、
部分成功の扱いを変更に応じて確認する。
保存・通信・表示の責任を混同せず、サーバー確定前に成功を確定しない。

移行や削除の手順は対象、バックアップ、復旧方法を具体化する。
本番データの変更や破壊的操作は既存の明示承認を確認する。
保存契約の変更は[独立レビュー](ownership.md)の対象。
