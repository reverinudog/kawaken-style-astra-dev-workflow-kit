# 承認済みの作業を順に進める

「離席するので順に進めて」「これらを終わらせて」で使う。例を読んだこと自体を実行許可にしない。

1. 対象タスク、依存順、各完了条件、Git完了を含むかを現在の依頼から確定する。
2. 未決の製品判断を残したタスクは実装列へ入れない。調査だけを任されたものは調査結果が終点。
3. 親が実装・自己レビュー・必要な独立レビュー・修正・検証を一単位で完了する。工程ごとの再予約を利用者に要求しない。
4. 前提が完了してから後続へ進む。前提が失敗した時は依存する後続を止め、独立して承認済みの作業は進める。
5. 中断する場合は完了範囲、未完、原因、再開点、未統合のbranchを記録する。未検証の作業をdoneや成功へ変えない。

Goalは明示依頼時だけ設定する。将来の時刻や繰り返し実行を依頼された場合は利用環境の正式なautomationを使う。
現在の連続作業やHTML提出待ちのために定期的なLLM起動を追加しない。
進行中の質問・訂正は元の目的へ取り込み、明示的に中止・差替えがなければ作業を続ける。

依頼例：指定したタスクを順に実装・レビュー・修正・検証し、PROJECT.mdの範囲で各ハンドオーバーまで進めて。
最後に各タスクの完了・未完・未着手と理由を簡潔に示す。
