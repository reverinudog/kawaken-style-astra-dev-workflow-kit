# Kawaken style Astra Dev Workflow Kit

CodexでAstraを使ってゲーム・アプリ・Webサービスを開発するための、運用ルール・スキル・テンプレート・補助ツール集です。調査、設計、実装、レビュー、検証、作業記録、Gitでの引き継ぎを対象にしています。

AGENTS.mdとスキルを通じてCodexに作業手順を指示し、同梱のツールで文書検査、HTMLフォームの回答保存、外部AIへの相談などを補助します。独立したAI実行環境ではなく、モデルの実行、権限管理、会話管理にはCodexを使用します。文書に定めたすべてのルールをプログラムで強制する仕組みではありません。

Kawakenの開発運用をもとに構成した非公式のキットです。OpenAI公式製品ではありません。特定のゲームのコード・素材・物語・仕様、個人情報、元の製品のGit履歴は含めていません。[MITライセンス](LICENSE)で利用・変更・再配布できます。

## 主な機能

| 機能 | 内容 |
| --- | --- |
| 開発手順 | 依頼の目的、変更範囲、維持すべき動作、完了条件を整理し、調査・実装・レビュー・検証を行う手順 |
| タスク管理 | 作業の仕様と完了条件の記録、タスク一覧の表示、選択した作業の開始 |
| HTMLによる説明と回答 | 説明・比較資料の表示、選択式回答、自由記入、下書き保存、提出、Codexへの通知 |
| レビューと検証 | Astraによる自己レビュー、必要な条件での独立レビュー、変更箇所に応じたテストの選択 |
| 専門領域の確認 | UI、保存データ、互換性、認証・権限、製品内AIの入出力、メディア制作、配布時の確認手順 |
| 教訓の記録 | 不具合の再発条件・原因・予防策をLESSONに記録し、次の関連作業で参照する手順 |
| 引き継ぎ | 作業結果、検証結果、未完了事項の記録と、承認された範囲でのcommit・push・統合・後片付け |
| 外部AIへの相談 | Geminiに画像や創作内容を相談するクライアントと、ChatGPTのGPT-6 Proへ相談するための資料作成ツール・操作手順 |
| 導入・保守ツール | 実行環境の確認、必要ファイルの配置、文書の参照検査、配布内容・Git履歴の検査 |

23の運用手順と19のスキルを収録しています。詳細は[収録機能の対応表](docs/harness/coverage.md)を参照してください。

通常の調査・設計・実装・修正・最終検証は主担当のAstraが行います。独立レビューは、高リスクの変更など[定めた条件](docs/harness/workflows/ownership.md)に該当する場合に追加します。

## 必要な環境

基本の実行環境はPython 3.10以降、Node.js 22以降、Gitです。追加のnpm・pipパッケージは必要ありません。機能ごとの条件は次のとおりです。

| 機能 | 追加で必要なもの |
| --- | --- |
| Astraによる開発作業 | CodexでAstraを利用できる環境 |
| HTML表示・回答による自動再開 | Codexデスクトップ、ブラウザ操作機能、同じタスクへの通知接続 |
| Geminiへの相談 | Gemini APIキーとAPIの利用条件・課金設定の確認 |
| GPT-6 Proへの相談 | ChatGPTへのログイン、指定モデルの利用権、ブラウザでのファイル添付操作。OpenAI APIキーは使用しない |
| GitHub操作 | GitHub CLI（gh）、認証、対象リポジトリへの権限 |
| 画像・音声・動画の制作 | 導入先で選んだ制作ツール、素材、必要な利用権 |

外部の生成エンジンや配布サービスは同梱していません。アカウントへのログイン、APIキーの発行、契約・課金の選択、管理者承認は利用者が行います。APIキーはチャットに貼り付けず、セットアップ時の非表示入力で設定します。

## 導入手順

1. このリポジトリをダウンロード、またはgit cloneでローカルに取得します。
2. 導入先のプロジェクトをCodexで開きます。
3. 取得したキットの[SETUP.md](SETUP.md)を読むように指示し、導入先を指定してセットアップを依頼します。

依頼例：

> Kawaken style Astra Dev Workflow KitのSETUP.mdを読み、このプロジェクトにセットアップしてください。

Codexが既存のルールと実行環境を確認し、必要なファイルの配置、既存文書との統合、PROJECT.mdの設定、検証を行います。既存のAGENTS.md、package.json、タスク、回答、個人スキルを一括上書きする手順ではありません。配置ツールは同名で内容の異なるファイルを保持し、Codexが差分を確認して統合します。

PROJECT.mdには、使用言語、起動・テスト方法、保存データの扱い、Gitの統合先、引き継ぎ時に実行してよい操作などを記録します。製品自身のLICENSEは保持し、このキットのMITライセンス表記をdocs/harness/LICENSEに配置します。

セットアップでは、設定の存在、通信を行わない試行、実際の接続成功を区別して確認します。外部AIへの実資料送信や有料生成は、セットアップだけでは開始しません。詳細は[導入手順](docs/harness/setup.md)を参照してください。

## 依頼例と動作

以下はCodexへの依頼例です。スキルとAGENTS.mdが、依頼に対応する手順を案内します。

| 依頼例 | 対応する作業 |
| --- | --- |
| ぬ / 次なに | タスク一覧をHTMLで表示する。利用者が作業を選択して提出すると、そのタスクの作業を開始する |
| 仕様を相談したい。まだ実装しないで | 調査と比較案の提示を行い、決まった内容を仕様として記録する。実装は開始しない |
| この不具合を直して | 影響範囲を調査し、修正、レビュー、必要な検証を行う |
| 後でやるタスクに追加して | 仕様と完了条件を記録し、一覧へ登録する。実装は開始しない |
| Geminiレスキュー | 画像や文章を資料としてGeminiに相談し、Astraが回答を検討する |
| GPT-6 Proに相談して | 必要な差分を含む資料を作成し、ChatGPTの指定モデルに相談する |
| LESSONに残して | 再発条件・原因・予防策を記録し、次の関連作業で参照できるようにする |
| 順番に進めて。離席します | 承認済みのタスクを依存関係に従って進め、結果と未完了事項を記録する |
| ハンドオーバー | 記録・教訓・検証結果を更新し、今回の承認とPROJECT.mdに定めた範囲のGit操作を行う |
| リリースノートを作って | 前回の配布版からの変更を、利用者向けの説明として整理する |

「ぬ」など、文脈上意味を持たない一文字をタスク選択のショートカットとして扱います。質問への短い回答と区別し、タスクが未登録なら空の一覧を表示します。

## HTML回答フォーム

説明や修正案をCodex内蔵ブラウザに表示し、項目ごとの選択と自由記入を受け付けます。下書きはブラウザ内に保存され、一覧で内容を確認してから一括提出できます。

提出後は回答をPCに保存し、接続済みのCodexデスクトップに通知して、同じタスクを再開します。「PCへの保存」「Codexへの通知」「再開したタスクでの受領」は別々の状態として表示します。通知が未接続の場合は自動再開できません。

同じ資料を更新するときはURLと保存キーを保持し、更新前の回答も保管します。未提出の入力は自動送信しません。モデルの再開は提出イベントで行い、回答待ちのためにLLMを常時実行しません。

説明専用HTMLは回答の自動再開機能と独立して使用できます。詳細は[HTML回答の手順](docs/harness/workflows/html-feedback.md)を参照してください。

## 制約と検証状況

公開、課金、破壊的操作、製品の意味を変える判断は、現在の依頼と導入先の承認範囲に従います。秘密情報や個人情報の検査は、すべての混入を検出する保証ではありません。配布前や外部送信前には、内容と対象範囲の確認も必要です。

v0.4.0で確認した範囲は以下のとおりです。

| 対象 | 確認結果 |
| --- | --- |
| Windows・macOS・Linux | Node.js 22 / Python 3.10のCIが成功。Windowsは41件、macOS/LinuxはWindows専用の1件を除く40件が成功 |
| 導入と更新 | 新規プロジェクト、既存プロジェクト、CommonJS環境への配置、既存設定・LICENSEの保持、再実行を確認 |
| 回答保存と秘密情報 | 回答の保存・再開、保存先のGit除外、リンク先への書き込み拒否、APIキーをエラーに表示しない処理を確認 |
| HTML回答からの自動再開 | Windows版Codexデスクトップで、提出・同じタスクの再開・回答受領を確認 |
| Gemini | 認証とモデル情報の取得を確認。生成は未確認 |
| GPT-6 Pro | ChatGPTへのログインと6 Proの選択表示を確認。実資料を添付した相談は未確認 |

macOS/LinuxでのCodexデスクトップ接続、スマートフォン・LAN/Tailscale経由の接続は実機未検証です。外部AIへの実際の相談を含め、導入先の環境と利用権に依存する機能は、その環境で確認してください。

HTMLの自動再開はデスクトップ接続アダプターを使用します。Codexの更新後も互換性が保証される公開APIではないため、更新によって接続の修正が必要になる場合があります。

詳しい結果は[検証記録](docs/harness/validation.md)、データの保管・送信範囲は[セキュリティの説明](SECURITY.md)、公開前の確認は[配布手順](docs/harness/publication.md)を参照してください。

## 保守用コマンド

このリポジトリでは次のコマンドを使用できます。

```sh
npm run docs:check
npm test
npm run test:feedback
npm run test:setup
npm run harness:doctor
npm run harness:scan
```

導入先では既存のpackage.jsonを維持するため、[導入手順](docs/harness/setup.md)に記載した直接実行コマンドを使用できます。これらはキット自体の検査です。導入先製品の動作試験は、その製品に合わせて別途実施します。

変更を加える場合は[CONTRIBUTING.md](CONTRIBUTING.md)と[文書の配置](docs/harness/documentation-map.md)を参照してください。
